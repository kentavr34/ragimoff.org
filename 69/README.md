## 2. ЦЕЛЬ: ЧТО ТАКОЕ «НОВЫЙ КОНЦЕПТ»

Не «новый дизайн страницы». Новая **система управления дизайном**.

### Проблема, которую решаем

Сейчас на сайте **нет единого концептуального управления**. Каждая страница — отдельный HTML,
размеченный вручную, «как если бы работали в Word». Изменение одного параметра (шрифт, отступ,
цвет) требует правки в десятках мест. При 160 страницах это 160 работ.

**Прецедент:** при попытке применить концепт как CSS поверх чужой вёрстки — вид не менялся,
потому что классы разметки не совпадали с классами стилей. Это уже стоило нескольких провалов
(сессии 29–30.09.2026).

### Что должно получиться

**Поменял значение в одном месте — изменилось везде.** Владелец формулирует так:

> «Как изменение темы в мобильных телефонах: выбираешь один файл, загружаешь этот файл стиля,
> темы — визуально меняются и значки, и цветовой фон, и шрифты, и иконки, и анимации,
> всё концептуально меняется.»

### Обязательное требование

Концепт применяется **сначала на ОДНОЙ странице**. Проверка приёмки: при изменении параметра
в одном файле он меняется во всех блоках этой страницы. Только после этого — расширение.

## 3. АРХИТЕКТУРА КОНЦЕПТА (утверждена владельцем 10.11.2026)

### 3.1 Пять слоёв

```
L0  FOUNDATIONS   токены: цвет, шрифт, пространство, радиус, тень, движение, z-index
L1  BASE          reset, типографика, сетка, prose, доступность
L2  COMPONENTS    кнопка, карточка, бейдж, форма, галерея, читалка, hero
L3  PATTERNS      секции: шапка секции, CTA-полоса, полоса цифр, лента карточек
L4  THEMES        dark / light / sepia — только переопределение L0-токенов
```

**Правило:** страница не содержит стилей. Только классы компонентов.
Любой `style="..."` в HTML — ошибка сборки.

**Технология:** нативные CSS Custom Properties + `@layer` + `:where()` + `clamp()` +
container queries. Без Tailwind, без CSS-in-JS, без фреймворков — сайт статический,
сборка на Python.

### 3.2 Токены — один источник

`tokens.json` → генератор `build_tokens.py` → `tokens.generated.css`.

Цвета называются **по роли, а не по цвету**: `--text`, `--surface`, `--accent`, `--bg`,
а не `--n-gold`, `--n-milk`, `--n-smoke`. При смене палитры имя не должно врать.

### 3.3 Типографическая шкала

Модульная **1.25 (major third)**, fluid через `clamp()`:

```
step-1  13 → 14      step3   31 → 33
step0   16 → 17      step4   39 → 41
step1   20 → 21      step5   49 → 51
step2   25 → 26      step6   61 → 64
```

Правило: **H1 — step5–6, H2 — step4, H3 — step2, тело — step0.**
Локальные `font-size` вне токенов запрещены.

**Также исправить:** сейчас H1 главной 32 px, а H2 секций 77.76 px — иерархия перевёрнута.

### 3.4 Шрифты — по ролям, и СВОИ

Владелец требует **собственные шрифты**, а не Georgia / Garamond:

| Роль | Токен | Где | Статус |
|---|---|---|---|
| Рукописный живописный | `--font-hand` | подпись, имя в hero, лозунг блока | **СОЗДАТЬ** |
| Строгий заголовочный | `--font-display` | H1, H2, крупные цифры | **СОЗДАТЬ** |
| Выразительный подзаголовочный | `--font-sub` | надзаголовки, рубрики | **СОЗДАТЬ** |
| Body / UI | `--font-text` | интерфейс, кнопки, карточки | доработать |
| Чтение | `--font-read` | читалка книг, длинные тексты | доработать |
| Цифры | `--font-num` | метрики, цены, номера | доработать |

**Обязательное требование к каждому:** 14 азербайджанских знаков — `ə Ə ı İ ş Ş ç Ç ğ Ğ ö Ö ü Ü`.
Проверять **парсингом cmap**, а не глазами. Шрифт без них не падает видимо — браузер молча
подставляет другую гарнитуру для этого одного символа, и буква выбивается из строки.

**Проверено ранее:** `marggraff-kursiv.woff` — 99 глифов, ноль азербайджанских.
Исходника (.glyphs/.ufo/.sfd) в проекте нет. Системные рукописные Windows (Inkfree,
Segoe Script, Gabriola, Mistral, Vivaldi, Freestyle Script) — `Ə` нет ни у кого.
Cormorant Garamond / Alegreya / Manrope — `Ə` есть в блоке latin-ext (`U+0100-02BA`),
и сторонний CSS разбивает эти знаки на два сабсета — **должны поставляться оба**.

### 3.5 Слепые пятна: компонент `prose`

Это дефект, который владелец описал отдельно: **обычный текст между боксами и блоками
в мобильной версии не имеет отступа ни сверху, ни снизу.**

Решение — компонент свободного текста:

```css
.prose {
  max-width: 68ch;
  margin-inline: auto;
  margin-block: var(--r3);        /* 40px телефон / 60px десктоп */
  font: 400 var(--step0)/1.65 var(--font-text);
  text-align: left;
  hyphens: auto;
}
.prose > * + * { margin-top: var(--r1); }
```

Плюс типология, чтобы «просто текста» на сайте не осталось: `prose`, `section-lead`,
`note`, `quote`, `caption`.

Сторож в `verify.py` валит сборку, если текст без класса и без отступа.

### 3.6 Моушен — пять уровней

| Уровень | Технология | Где | Вес |
|---|---|---|---|
| L1 micro | CSS transition | кнопки, ссылки, карточки | 0 KB |
| L2 reveal | scroll handler + CSS | появление секций | ~2 KB |
| L3 scroll-driven | CSS `animation-timeline` + JS fallback | ленты карточек, прогресс | 0–5 KB |
| L4 cinematic | скраб кадров | hero главной | 1–3 MB медиа |
| L5 3D | Three.js / WebGL | **только главная**, lazy, desktop | 150–400 KB |

**Решение владельца по 3D:** на современном интернете это допустимо — «хотя бы на главной
в блоке героя для первого вау-эффекта». Но обязательно: lazy-загрузка после первого экрана,
fallback-постер, отключение при `prefers-reduced-motion` и `saveData`.

**Blender / Higgsfield / graybox — это НЕ runtime.** Это пайплайн производства контента:
превиз сцены → рендер playblast → генерация видео по референсу. Результат — видеофайл
для hero, а не 3D в браузере.

**Важно про reduced-motion:** владелец системно держит «уменьшить движение» в Windows,
поэтому браузеры глушат анимацию, и корректный motion-код выглядит сломанным.
Глушить нужно только **резкое** движение (бесконечные циклы, параллакс, большие пролёты),
а мягкие появления — opacity, сдвиг на несколько px, выход из маски — **оставлять включёнными**.

### 3.7 Компонентный реестр — обязателен

30 компонентов, у каждого: один CSS-файл, один набор токенов, один пример в
`examples/kitchen-sink.html`. Полный список — в `docs/RAGIMOFF_DESIGN_SYSTEM_RESTRUCTURE.md`, §6.

**Правило:** новый блок нельзя добавить на страницу, пока он не зарегистрирован в
`docs/COMPONENT-REGISTRY.md` и не имеет примера.

## 4. СТРУКТУРА СТРАНИЦ И ЛОКАЛИЗАЦИЯ

### 4.1 Книги

```
books/
├── clinical-psychiatry/
│   ├── book.json          манифест: название, языки, цена, ISBN, обложка
│   ├── index.html         язык по умолчанию
│   └── az/ ru/ en/ tr/    только объявленные в манифесте языки
```

Язык **не может** быть верхним уровнем: у книг разный набор языков
(«Клиническая психиатрия» — 4, остальные — 3). Генератор читает манифест и создаёт
только существующие версии. `hreflang` — только на них.

### 4.2 Уменьшение числа страниц в 3 раза

Владелец предложил: одна страница на сервис + тексты отдельно, номер строки как локация.
**Направление верное, реализация рискованная.** Что не так:

**Номера строк хрупкие.** Вставил абзац — все номера ниже сдвинулись, переводы разъехались.
Номер не хранит разметку (ссылки, выделения), не решает плюрализацию
(«1 сессия / 2 сессии / 5 сессий»), не переносит разный порядок слов.

**Клиентская подстановка убивает SEO.** Один URL на три языка — поисковик видит только
язык по умолчанию, `hreflang` не работает, ссылкой на русскую версию нельзя поделиться,
текст появляется после JS → хуже LCP и CLS.

**Правильное решение — SSG + семантические ключи:**

```
design/templates/training.html.j2       один шаблон на ТИП страницы (9 типов, не 160)
content/az/telim/klinik-psixologiya.yaml
content/ru/telim/klinik-psixologiya.yaml
content/en/telim/klinik-psixologiya.yaml
```

Ключи **смысловые, не порядковые**: `hero.title`, `facts.hours`, `price.total`.
Параллельность 1:1 сохраняется, но ключ не сдвигается при вставке абзаца.

Сборка генерирует отдельные URL для каждого языка — SEO и hreflang сохраняются.
Валидатор в `verify.py`: набор ключей во всех языках совпадает, пустых нет, лишних нет —
иначе сборка красная.

**Выигрыш владельца сохраняется полностью: один дизайн, один шаблон, тексты отдельно.**

### Последовательность блоков главной (по прямому указанию владельца)

**герой → специалисты → книги → обучение → консультации → бизнес-тренинги →
просвещение и мифы → блог → Telegram → подвал**

**Главный принцип:** главная — посадочная страница. Каждый блок показывает главное
и **отдаёт** человека на подробную страницу. Ни один блок не пытается рассказать всё сам.
**Во всех блоках главной должна быть отсылка.**

Главный принцип: **сайт не утверждает превосходство — он его предъявляет.**
Не «я эксперт», а «вот документ, вот книга, вот источник — проверь».
Читатель делает вывод сам. Это сильнее любого прилагательного.

**Формула каждого блока: факт → доказательство → проверка → действие.**
Ни один блок не начинается с «мы».

### Порядок блоков главной

```
МИФ:      «Мелипрамин формирует рефлекс пробуждения»
НА САМОМ ДЕЛЕ: вызывает задержку мочеиспускания как побочный эффект;
              кардиотоксичен; известны случаи смерти. Не рекомендован.
ИСТОЧНИК: «Клиническая психиатрия», раздел …, с. …
```

Разрушение мифа должно попадать в **ложное убеждение**, которое мешает лечиться,
а не просто в «это неправда». Темы: энурез (Мелипрамин, Энурезин — источник PDF
Минздрава АР, акупунктура), депрессия, панические атаки, семейная терапия.

На главной — 3 превью со ссылкой на страницу, на странице услуги — полный разбор.

### Копирайтинг — правила владельца

**Запрещено:** слово «доказательство» в заголовках; прямая самохвальба;
штампы типа «Каждая книга — доказательство направления»; рубленые короткие фразы
(«23 года практики. Диплом. Сертификат.»); хвалебные прилагательные без факта.

**Как надо:** прилагательные описательные, но не хвалить напрямую. Присоединять факт
к его следствию, чтобы факт приходил уже осмысленным, и добавлять строку о том,
что это даёт читателю. Показывать, что аналога в мире нет — через перечень фактов.

**Пример замены:** «Уникальный опыт» → «31 минута. Реальный случай…»

**Все три языка переписываются в одном проходе** — иначе тон разъезжается при переключении.

для сравнения. Работа идёт только над новым концептом.

## 8. ПЛАН ВНЕДРЕНИЯ

| Этап | Что | Критерий приёмки |
|---|---|---|
| **0. Заморозка** | точка возврата, фиксация текущего состояния | тег/бэкап на месте |
| **1. Токены** | `tokens.json` + генератор + семантические имена | все цвета/шрифты/отступы из токенов |
| **2. Слои** | `@layer reset, tokens, base, components, patterns, themes, utilities` | 0 `!important` вне утилит |
| **3. Prose** | компонент свободного текста + сторож | 0 нарушений на тестовой странице |
| **4. Шрифты** | свои гарнитуры с полным азербайджанским покрытием | парсинг cmap: 14/14 у каждого |
| **5. Компоненты** | по реестру, по одному, с примером | kitchen-sink совпадает со страницами |
| **6. Темы** | dark / light / sepia | контраст ≥ 4.5:1, скриншоты обеих тем |
| **7. Моушен** | L1–L3, затем выборочно L4 / L5 | LCP < 2.5 s, reduced-motion корректен |
| **8. Сторожа** | `verify.py`: inline-style, prose, контраст, overflow | 0 замечаний перед публикацией |
| **9. Одна страница** | применение концепта на одной странице | **изменение в одном файле меняет всё** |
| **10. Расширение** | перенос на остальные типы страниц | только после утверждения |

**Порядок неслучаен.** Сначала токены и слои, потом компоненты, только потом темы и 3D.
Если начать с 3D — оно ляжет на нестабильную основу и развалится при первой смене темы.
