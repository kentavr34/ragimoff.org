## Этажи

| Этаж | Где | Что лежит | Объём | Назначение |
|---|---|---|---|---|
| **Верхний** | Redis | светофор `current_task`, горячий кэш | — | быстрый вход в контекст |
| **Средний** | Postgres `dialog_history` | **сокращённые реплики по 308 символов** | 175 554 строки | поиск, дешёвый по токенам |
| **Граф** | LightRAG | сущности и связи | — | семантический recall |
| **Нижний** | **полные тексты** | первоисточники целиком | ? | глубинный доступ по тегу/ссылке |

**Логика замысла:** верхний слой даёт быстрый и дешёвый поиск — чтобы не тратить токены
на полные тексты. Найдя нужную реплику, по **тегу** спускаешься к полному тексту.

**Замысел Кенана:** верхний магазин — не 308 символов как таковое, а **связка**:
тег + реплика. По поисковому запросу находишь нужное, и связка ведёт к полному тексту.

# 5. КАК ПОДКЛЮЧАТЬСЯ

## Рукопожатие

```bash
MCP="http://45.67.216.36:9626/mcp"

# 1. initialize → забрать mcp-session-id из ЗАГОЛОВКОВ ответа
curl -s -D - -o /dev/null -X POST "$MCP" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
      "protocolVersion":"2024-11-05","capabilities":{},
      "clientInfo":{"name":"hermes","version":"1.0"}}}'
# → mcp-session-id: <SID>

# 2. вызов инструмента с этим заголовком
curl -s -X POST "$MCP" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: <SID>" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{
      "name":"dialog_history","arguments":{"project":"ragimoff","limit":400}}}'
```

Ответ приходит в формате **SSE** — строки `data: {...}`. Парсить: отрезать `data: `,
брать JSON-строки.

## Инструменты (7)

| Инструмент | Назначение | Параметры | Токен |
|---|---|---|---|
| `recall` | семантический recall из LightRAG | `query`, `mode=mix`, `top_k=8` | нет |
| `dialog_history` | **точные последние строки диалога** | **`project`, `limit` ТОЛЬКО** | нет |
| `search_memory` | полнотекстовый поиск (ILIKE) по истории | `query`, `project`, `limit` | нет |
| `memory_status` | здоровье: LightRAG + строки Postgres + Redis | — | нет |
| `current_task_get` | светофор, статус полосы проекта | `project` (пусто = все) | нет |
| `remember` | записать знание в граф LightRAG | — | **да** |
| `current_task_set` | записать статус полосы | — | **да** |

**Токен:** `BRAIN_MCP_TOKEN`, лежит на сервере в `/opt/claudia/brain_mcp.token` (600).
Значение в чат/отчёт/git не печатать никогда.

# 6. ГРАБЛИ (проверено 10.11.2026)

| Грабля | Проявление | Как обойти |
|---|---|---|
| **Кириллица в аргументах** | `'utf-8' codec can't decode byte 0xea` | передавать через файл с `ensure_ascii=False`, слать `--data-binary @-` |
| **`offset` не поддерживается** | в схеме только `project` и `limit` | увеличивать `limit` (400 → 1200 работает) |
| **Реплики усечены до ~308 символов** | полного текста через MCP не получить | это замысел, не баг: подниматься по тегу к первоисточнику |
| **`recall` / `search_memory` по ragimoff пусто** | `No relevant context found` | проект не проиндексирован в графе LightRAG; использовать `dialog_history` |
| **Слишком большой `limit`** | запрос может упасть по таймауту | 1200 работает стабильно за ~60 с |
| **SSE-обёртка** | обычный JSON-парсер не берёт | отрезать `data: ` перед парсингом |

**Из прошлого разбора (25.09.2026, историческое):** тогда ЦНС была сломана —
`relation "memory.dialog_compat" does not exist` для всех проектов, `recall` не работал
по ragimoff. **На 10.11.2026 всё работает: 175 554 строки, LightRAG healthy.**
