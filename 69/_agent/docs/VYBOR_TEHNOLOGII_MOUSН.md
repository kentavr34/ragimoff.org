# ВЫБОР ТЕХНОЛОГИИ МОУШЕНА — ресерч и обоснование

Составлено 11.11.2026 по требованию владельца: «если я говорю, что надо
сделать Motion, ты должен найти лучшие инструменты. Не я тебе должен
говорить Blender, MCP... Ты должен сам провести ресерч, найти лучшие
инструменты, существующие в мире сегодня, и посмотреть, какие из них
мы можем прямо сейчас применить. Составить список, сделать выбор на
технологии. А после этого из этой технологии алгоритм составить».

Порядок здесь именно такой: **ресерч → список → выбор → алгоритм**.
Ничего не выбрано «по привычке» — у каждого пункта источник.

## 1. Что выяснил ресерч (июль–сентябрь 2026)

**JS-библиотеки: единого победителя НЕТ, выбор идёт по задаче.**
Источник: annnimate.com/compare/best-animation-libraries (обновлено 20.07.2026)

| Задача | Победитель | Почему |
|---|---|---|
| Прокрутка, закреплённые секции, сложная хореография по таймлайну | **GSAP + ScrollTrigger** | «gsap.timeline() и набор плагинов (SplitText, Draggable, CustomEase) не имеют реального эквивалента». С версии 3.13 (2024) **полностью бесплатен, включая все плагины** |
| Плавная прокрутка (инерция) | **Lenis** | «Не движок анимации, а слой инерции прокрутки. Стандарт де-факто на творческих сайтах. Использовать ВМЕСТЕ с библиотекой, а не вместо» |
| Простые появления при прокрутке без настройки | **AOS** (~14 КБ) | Быстрее всего для базовых fade/slide, но разработка замедлилась |
| Базовые переходы и hover | **чистый CSS** | Ноль стоимости загрузки |

**CSS-анимации по прокрутке стали пригодны для прода.**
Источник: web-platform-dx.github.io/web-features-explorer (статус Newly Available с 27.10.2026)
Поддержка: Chrome 115+ (2023), Safari 26 (сентябрь 2025), **Firefox 159 (27.10.2026)**.
То есть впервые поддержка есть во всех трёх движках. Охват — около 7% загрузок страниц.
Свойства: `animation-timeline`, `scroll-timeline`, `view-timeline`.
**Вывод:** можно делать анимации по прокрутке БЕЗ JavaScript, но охват ещё не полный —
значит нужен запасной вариант для остальных.

**Как устроен сайт, получивший Awwwards (эталон уровня).**
Источник: ecrin.digital — разбор Hear.ai (Awwwards Honorable Mention, март 2026)

Ключевое из разбора, что применимо к нам дословно:
- «Прокрутка как повествование: вместо прыжков между секциями содержание
  разворачивается как история. Каждое взаимодействие раскрывает новый слой».
- «Подход работает потому, что ценность предложения **последовательна**».
- «**Каждое движение служит цели**».
- Стек: **Motion + Lenis** для анимации и плавной прокрутки, **Three.js** для 3D.
- Приёмы: сетка точек с волной при прокрутке; линии магнитного поля в герое;
  шагомер с тремя ступенями; дверь-червоточина через `offset-path`.
- Главный вывод авторазбора: «**Движение должно демонстрировать возможность,
  а не украшать**».

## 2. Список для рассмотрения и решение по каждому

| Технология | Решение | Обоснование |
|---|---|---|
| **GSAP + ScrollTrigger** | **ВЗЯТЬ** | Лучший в мире для хореографии по прокрутке, бесплатен целиком с 3.13. Наш герой — длинная секция (2.5 экрана) со ступенчатым раскрытием: это ровно его задача |
| **Lenis** | **ВЗЯТЬ** | Инерция прокрутки — то самое «живое, не мёртвое» ощущение, о котором говорил владелец. Стандарт де-факто, сам не рисует, только сглаживает |
| **CSS scroll-driven animations** | **ВЗЯТЬ как основу, с запасным вариантом** | Ноль JavaScript для базовых раскрытий. Поддержка стала полной лишь 27.10.2026, поэтому обязателен запасной путь через обычный обработчик прокрутки |
| **Three.js** | **ВЗЯТЬ, уже работает** | Сеть интеллекта в герое. В разборе Awwwards-сайта — тот же выбор для 3D |
| **Motion (бывший Framer Motion)** | **НЕ БРАТЬ** | Заточен под React. У нас чистый HTML и шаблон — приносит зависимости без выгоды |
| **Anime.js v4** | **НЕ БРАТЬ** | Хорош для простой промежуточной анимации, но у нас сложная хореография — это ниша GSAP |
| **AOS** | **НЕ БРАТЬ** | Разработка замедлилась, а его работу закрывает CSS с запасным вариантом. Лишние 14 КБ |
| **Remotion** | **ОТЛОЖИТЬ** | Рендерит видео из React — нужно для видеороликов, не для моушена на странице |
| **Blender (через MCP)** | **ОТЛОЖИТЬ** | Владелец запретил держать локально. Для героя не требуется: живая сцена в браузере лучше 120 отрендеренных кадров. Нужен будет для отдельного видео |
| **matter.js** | **ОТЛОЖИТЬ** | Физика нужна для отдельных элементов (например, разрушение мифа). В герое и блоках не нужна — там хореография, а не физика |

## 3. Алгоритм работы с моушеном (из выбранной технологии)

1. **Разметка объявляет намерение, а не способ.** Блок получает атрибут
   вида `data-motion="rise"` — что должно произойти. Способ задаёт скрипт.
   Это разделение позволяет заменить GSAP на другое без правки разметки.
2. **Базовое состояние всегда видимое.** Анимация только улучшает появление.
   Причина оплачена дважды: при системном «уменьшить движение» анимации
   глушатся, и блок, ждущий анимации, остаётся невидимым — страница пустеет.
3. **Порядок раскрытия задаёт аргументацию, а не красоту.** Блоки выходят
   по одному, в порядке убеждения: кто → чем доказал → чему учит.
4. **Ступени вместо одновременности.** Задержка между элементами 60–90 мс:
   так глаз ведут, а не ошеломляют.
5. **Один герой — одна сцена.** В герое работает сеть интеллекта (Three.js)
   плюс ступенчатое раскрытие текста. Больше в герое движения не добавлять:
   перегруз движения читается как дешёвый эффект.
6. **Приём из разбора Awwwards:** движение демонстрирует возможность.
   Сеть показывает мышление и движение к цели, а не «просто красиво».
7. **Запасной вариант обязателен** для всех CSS-анимаций по прокрутке:
   `@supports (animation-timeline: scroll())` плюс обработчик прокрутки.

## 4. Что предстоит проверить на практике

- [ ] GSAP подключён локально (без CDN) и не утяжеляет страницу сверх меры
- [ ] Lenis сглаживает прокрутку и НЕ ломает прилипание героя
- [ ] CSS-раскрытия работают в Chrome, Safari и Firefox; в остальных — запасной путь
- [ ] При «уменьшить движение» страница полностью видима и без движения
- [ ] На телефоне моушен не превращается в тряску: параллакс отключён
