# 1. Диагноз: почему правки расползаются

| # | Причина | Следствие |
|---|---|---|
| 1 | **Токены смешаны с компонентами.** `:root` содержит и палитру, и шрифты, и сетку; дальше 1000 строк селекторов. | Нельзя поменять тему или шкалу, не рискуя сломать вёрстку. |
| 2 | **Цвета названы по цвету, а не по роли.** `--n-gold`, `--n-milk`, `--n-smoke`. | При смене палитры «золото» может стать синим — имя врёт. |
| 3 | **Нет типографической шкалы.** Размеры задаются по месту (`31px`, `34.56px`, `77.76px`). | Иерархия плоская, H1 меньше H2, кегли «пляшут» между страницами. |
| 4 | **Нет компонентного слоя.** Карточка программы, карточка услуги, карточка статьи — разные селекторы с похожей логикой. | Правка отступа в одном месте не доходит до остальных. |
| 5 | **Нет светлой темы.** Только тёмная палитра в `:root`. | Переход на светлую — переписывание половины файла. |
| 6 | **Свободный текст не имеет компонента.** Лечится селектором `main section > .sec-inner > p:not([class])` — то есть «всё, что забыли разметить». | Тот самый дефект: текст между блоками без отступов на мобильном. |
| 7 | **Нет сторожей на уровне системы.** `verify.py` проверяет ссылки и разметку, но не отступы, не контраст, не переполнение. | Дефекты находятся глазами Кенана, а не сборкой. |

# 2. Целевая модель: 5 слоёв дизайн-системы

```
L0  FOUNDATIONS   токены: цвет, шрифт, пространство, радиус, тень, движение, z-index
L1  BASE          reset, типографика, сетка, prose, доступность
L2  COMPONENTS    кнопка, карточка, бейдж, форма, галерея, читалка, hero
L3  PATTERNS      секции: шапка секции, CTA-полоса, полоса цифр, лента карточек
L4  THEMES        dark / light / contrast — только переопределение L0-токенов
```

**Правило слоёв:** страница не содержит стилей. Она содержит только классы компонентов. Любой `style="..."` в HTML — ошибка сборки.

**Технология:** нативные CSS Custom Properties + `@layer` + `:where()` + `clamp()` + container queries. Без Tailwind, без CSS-in-JS, без React — сайт статический, сборка на Python.

# 3. Управление токенами: один источник → CSS

## 3.1 Формат

`design/tokens/tokens.json` — единственное место, где задаются значения:

```json
{
  "color": {
    "brand":   { "gold": "#C9A961", "gold-soft": "#E2CC94" },
    "neutral": { "0": "#07090E", "50": "#0A0D14", "100": "#11141C",
                 "700": "#A8A296", "800": "#CFC8BB", "900": "#E3DDD1", "1000": "#F2EDE3" },
    "semantic": {
      "bg":        "{color.neutral.0}",
      "surface":   "{color.neutral.100}",
      "text":      "{color.neutral.900}",
      "text-muted":"{color.neutral.700}",
      "border":    "rgba(242,237,227,.12)",
      "accent":    "{color.brand.gold}",
      "on-accent": "{color.neutral.0}"
    }
  },
  "font": {
    "display": "'Cormorant Garamond', Georgia, serif",
    "text":    "'Manrope', system-ui, sans-serif",
    "read":    "'Alegreya', Georgia, serif"
  },
  "size": { "step-1": "0.8125rem", "step0": "1rem", "step1": "1.25rem",
            "step2": "1.5625rem", "step3": "1.953rem", "step4": "2.441rem",
            "step5": "3.052rem", "step6": "3.815rem" },
  "space": { "u": "8px", "r1": "calc(var(--u) * 2)", "r2": "calc(var(--u) * 3)",
             "r3": "calc(var(--u) * 5)", "r4": "calc(var(--u) * 8)" },
  "radius": { "sm": "8px", "md": "14px", "lg": "22px", "pill": "999px" },
  "motion": { "fast": "180ms", "base": "320ms", "slow": "600ms",
              "ease": "cubic-bezier(.2,.8,.2,1)" }
}
```

## 3.2 Генерация

`design/tokens/build_tokens.py` → `design/tokens/tokens.generated.css`.

- Меняешь `tokens.json` — пересобираешь один файл — изменения на всех страницах.
- Для светлой темы не переписываются компоненты: меняется блок `[data-theme="light"]` с семантическими токенами.
- Экспорт в JS (`tokens.json` читается на клиенте) — для canvas/Three.js, чтобы 3D-сцена брала те же цвета.

**Альтернатива без сборки:** держать токены прямо в `tokens.css`. Проще, но нет единого источника для JS и документации. Рекомендация — JSON + генератор: у вас уже Python-сборка, добавить один шаг дёшево.

# 4. Типографика и шрифты

## 4.1 Что не так сейчас

- H1 главной — **32 px**, H2 секций — **77.76 px**: иерархия перевёрнута.
- Размеры: 13 / 14 / 18 / 20 / 31 / 34.56 / 51.84 / 77.76 / 108 — не шкала, а набор.
- Три гарнитуры без ролей: непонятно, где какая обязательна.
- Рукописный шрифт — «слишком мягкий», текст слипается (замечание Кенана 08.11).

## 4.2 Целевая система

| Роль | Гарнитура | Где | Начертания |
|---|---|---|---|
| Display | Cormorant Garamond (variable) | H1, H2, крупные цифры | 300–600 |
| Text | Manrope (variable) | интерфейс, кнопки, карточки | 400–700 |
| Read | Alegreya (variable) | читалка книг, длинные статьи | 400, 400i, 600 |
| Accent (опционально) | рукописный RAGIM | только подпись/цитата, не тело | 400 |

**Шкала — модульная 1.25 (major third), fluid через `clamp()`:**

```
step-1  13px → 14px
step0   16px → 17px
step1   20px → 21px
step2   25px → 26px
step3   31px → 33px
step4   39px → 41px
step5   49px → 51px
step6   61px → 64px
```

Правило: **H1 — step5–6, H2 — step4, H3 — step2, тело — step0.** Никаких локальных `font-size` вне токенов.

**Читалка:** `max-width: 68ch`, `line-height: 1.7`, `font-family: var(--font-read)`, `hyphens: auto`, `text-wrap: pretty`. Отдельная тема читалки (sepia / light / dark) — через те же семантические токены.

**Шрифты:** self-hosted `.woff2`, `font-display: swap`, `unicode-range` для az/ru/en, preload только display-шрифта. Не грузить три гарнитуры на первую страницу — Read подключать только в читалке.

# 5. Темы: как переключать всё одной переменной

## 5.1 Семантические токены (обязательный минимум)

```
--bg, --bg-elevated, --surface, --surface-2
--text, --text-muted, --text-faint
--border, --border-strong
--accent, --accent-soft, --on-accent
--link, --link-hover
--shadow-color, --overlay
--focus-ring
```

Компоненты используют **только** эти имена. `--n-gold` остаётся внутренним именем палитры, но в компонентах — `var(--accent)`.

## 5.2 Темы

```css
:root, [data-theme="dark"] { --bg:#07090E; --text:#E3DDD1; --accent:#C9A961; ... }
[data-theme="light"]      { --bg:#F7F4EE; --text:#1A1A1E; --accent:#8A6A22; ... }
[data-theme="sepia"]      { --bg:#F2E8D5; --text:#2B2419; --accent:#7A5A1E; ... }
```

- Переключение: `data-theme` на `<html>`, сохранение в `localStorage`, `color-scheme` для нативных контролов.
- Проверка контраста: минимум **4.5:1** для тела, **3:1** для крупного текста и границ. Автотест на пары «текст/фон» из токенов.
- Изображения: в светлой теме — без инверсии; тени и стекло пересчитываются через `--shadow-color` / `--overlay`.
- Логотип и иконки — `currentColor` или маска, чтобы менять цвет темой.

# 7. «Слепые пятна»: свободный текст между блоками

Это главная системная дыра, которую вы описали.

## 7.1 Что происходит сейчас

Текст, который не попал в карточку или секцию с классом, наследует `margin: 0` из reset. На мобильном между двумя блоками он оказывается вплотную к границам — без воздуха сверху и снизу.

## 7.2 Решение: компонент `prose`

```css
.prose {
  max-width: 68ch;
  margin-inline: auto;              /* центрирование колонки, не текста */
  margin-block: var(--r3);          /* 40px телефон / 60px десктоп */
  padding-inline: var(--pad-inline);
  font: 400 var(--step0)/1.65 var(--font-text);
  color: var(--text);
  text-align: left;                 /* центр только для 1–2 строк */
  text-wrap: pretty;
  hyphens: auto;
}
.prose > * + * { margin-top: var(--r1); }
.prose h2 { font: 400 var(--step4)/1.15 var(--font-display); margin-top: var(--r3); }
.prose h3 { font: 500 var(--step2)/1.25 var(--font-text); margin-top: var(--r2); }
.prose ul, .prose ol { padding-left: 1.25em; }
.prose blockquote { border-left: 2px solid var(--accent); padding-left: var(--r2); font-family: var(--font-read); }
```

**Правила применения:**

1. Любой одиночный `<p>`, `<ul>`, `<blockquote>` внутри `main`, не входящий в компонент, **обязан** иметь класс `prose` (или быть внутри `.prose`).
2. Автоматическая страховка: `main > p:not([class])`, `section > p:not([class])` получают `margin-block: var(--r3)` — но это костыль, а не замена классу.
3. Сторож `verify.py` ищет текст без класса и без отступа и валит сборку.
4. Для коротких плашек-призывов (1–2 строки) — `.prose--center`, не более двух строк; длиннее — принудительно влево.

## 7.3 Типология текста (чтобы не было «просто текста»)

| Тип | Класс | Ширина | Выравнивание | Отступ |
|---|---|---|---|---|
| Свободный текст | `.prose` | 68ch | left | r3 сверху/снизу |
| Лид секции | `.section-lead` | ширина заголовка | center (1–2 строки) | r1 |
| Примечание | `.note` | 68ch | left | r2 |
| Цитата | `.quote` | 52ch | left | r3 |
| Список | внутри `.prose` | 68ch | left | r1 между пунктами |
| Подпись к фото | `.caption` | ширина фото | left | r1 |

# 8. Моушен-система: что, где и на чём

## 8.1 Уровни движения

| Уровень | Технология | Где | Стоимость | Риск |
|---|---|---|---|---|
| L1 Micro | CSS transition | кнопки, ссылки, карточки | 0 KB | нет |
| L2 Reveal | IntersectionObserver + CSS | появление секций, текста | ~2 KB | низкий |
| L3 Scroll-driven | CSS `animation-timeline: scroll()` + fallback JS | ленты карточек, прогресс | 0–5 KB | средний (Safari) |
| L4 Cinematic | скраб кадров / видео | hero главной | 1–3 MB медиа | высокий на мобильном |
| L5 3D | Three.js / WebGL | hero, спецблок | 150–400 KB JS | высокий |

## 8.2 Матрица: эффект → место → технология

| Эффект | Где уместен | Технология | Приоритет |
|---|---|---|---|
| Кинематографичный hero (кадры по скроллу) | главная | уже есть; заменить размытые кадры | **P0** |
| Reveal текста по строкам | заголовки секций | IntersectionObserver + CSS | **P0** |
| Горизонтальная лента карточек на вертикальном скролле | программы, блог | CSS scroll-timeline + JS fallback | **P1** |
| Магнитные кнопки и перекат текста | CTA | CSS + pointermove | P1 |
| Раскрытие изображений маской | галерея, блог | clip-path + IO | P1 |
| Бесконечная карусель логотипов | корпоратив, доверие | CSS marquee, 2 ряда | P1 |
| Bento-сетка | главная, корпоратив | CSS Grid | P1 |
| Таймлайн с прорисовкой линии | о специалисте | SVG stroke-dashoffset + scroll | P2 |
| 3D-объект (GLB) | hero или блок книги | Three.js + GLTFLoader, lazy | P2 |
| Стекло и частицы (glassmorphism) | hero, CTA | Three.js / CSS backdrop-filter | P2 |
| Видео-фон | hero | `<video>` + poster, mobile fallback | P2 |

## 8.3 Про Three.js — честно

Из ролика: glassmorphism, частицы, пролёт камеры между сценами. Это даёт премиальное впечатление, но:

- **Вес:** Three.js ~150 KB gzip + сцена/текстуры 300–800 KB.
- **Мобильные:** WebGL на слабых Android греет телефон и роняет FPS.
- **SEO/LCP:** 3D не должен быть LCP-элементом.

**Рекомендация:** один 3D-слой **только на главной**, ленивая загрузка после первого экрана, `prefers-reduced-motion` и `navigator.connection.saveData` → статичный постер. Сцена — не «летающие кубы», а сдержанная: стеклянная панель с логотипом R, частицы пыли в луче света, медленный пролёт камеры. Всё остальное — CSS.

## 8.4 Про Blender / Higgsfield / graybox

Это **не runtime-технологии**, а пайплайн производства контента:

1. **Blender + Higgsfield** — сделать превиз сцены (камера, свет, движение), отрендерить playblast, затем AI-видео по референсу. Результат — видеофайл для hero.
2. **Graybox без Blender** — то же, но сцена собирается в ChatGPT/Claude; подходит, если нужен один-два кадра.
3. **Tripo / image→3D** — получить GLB-модель (например, книга, символ R) и вставить в Three.js.

**Практический вывод:** Blender нужен не для сайта, а для **производства hero-видео**. У вас уже есть скраб кадров — правильнее заменить проблемные кадры на чистые, снятые по превизу, чем тащить 3D в браузер.

## 8.5 Бюджет движения

- LCP < 2.5 s на 4G.
- JS интерактива < 150 KB gzip (без 3D).
- 3D — только по запросу, < 400 KB, не на мобильных с `saveData`.
- Все анимации отключаются при `prefers-reduced-motion: reduce`, кроме мягких (opacity, ≤12 px).
- Никакого smooth-scroll, ломающего доступность.

# 10. План внедрения

| Этап | Что делаем | Результат | Критерий приёмки |
|---|---|---|---|
| **0. Заморозка** | Бэкап, тег, ветка | точка возврата | `live-backup` на месте |

| **2. Слои** | `@layer reset, tokens, base, components, patterns, themes, utilities` | предсказуемая специфичность | 0 `!important` вне утилит |
| **3. Prose** | компонент свободного текста + правило + сторож | текст между блоками с отступами | 0 нарушений на 3 страницах |
| **4. Компоненты** | по реестру, по одному, со примером | единые карточки/формы/кнопки | kitchen-sink совпадает с прод-страницами |
| **5. Темы** | dark/light/sepia | переключение без потери сути | контраст ≥ 4.5:1, скриншоты обеих тем |
| **6. Моушен** | L1–L3, затем выборочно L4/L5 | впечатление без потери скорости | LCP < 2.5 s, reduced-motion работает |
| **7. Сторожа** | `verify.py`: inline-style, prose, контраст, overflow | сборка валит дефекты | 0 замечаний перед публикацией |

**Порядок неслучаен:** сначала токены и слои, потом компоненты, только потом темы и 3D. Если сделать 3D раньше — оно будет натянуто на нестабильную основу и развалится при первой смене темы.

# 14. Структура страниц и локализация: оценка концепции

## 14.1 Книги: `books/<книга>/<язык>/` — да

Предложение верное. У книг **разный набор языков** («Клиническая психиатрия» — 4, остальные — 3), поэтому язык не может быть верхним уровнем.

```
books/
├── clinical-psychiatry/
│   ├── book.json              манифест: название, автор, ISBN, цена, языки
│   ├── index.html             язык по умолчанию (az)
│   ├── az/index.html
│   ├── ru/index.html
│   ├── en/index.html
│   └── tr/index.html
├── shizofreniya/
│   ├── book.json              languages: [az, ru, en]
│   ├── index.html
│   ├── az/index.html
│   ├── ru/index.html
│   └── en/index.html
└── ...
```

**Манифест книги** — единственный источник правды:

```json
{
  "slug": "clinical-psychiatry",
  "title": { "az": "Klinik Psixiatriya", "ru": "Клиническая психиатрия",
             "en": "Clinical Psychiatry", "tr": "Klinik Psikiyatri" },
  "languages": ["az", "ru", "en", "tr"],
  "default": "az",
  "cover": "cover.webp",
  "price": { "AZN": 28 },
  "isbn": "...",
  "reader": true
}
```

Генератор читает манифест и создаёт только те языковые версии, которые объявлены. `hreflang` — только на существующие. Нет «пустых» страниц-заглушек.

**Плюсы:** изоляция книги, честный hreflang, удобно добавлять язык одной записью в манифест.
**Минус:** без генератора каждая книга — ручная папка; лечится шаблоном.

---

## 14.2 Одна страница на сервис + тексты отдельно — направление верное, реализация рискованная

Сама идея — классическое **разделение представления и контента** (design / content). Это правильно. Но конкретная схема «номер строки = локация» и «подстановка при выборе языка» имеет проблемы.

### Что не так с номерами строк

| Проблема | Что происходит |
|---|---|
| **Хрупкость** | Вставили абзац в середину — все номера ниже сдвинулись, переводы разъехались. |
| **Нет контекста** | Переводчику `47` ничего не говорит; `training.klinik.hero.lead` — говорит. |
| **Разметка внутри строки** | Ссылка, `<strong>`, перенос — номер не умеет хранить структуру. |
| **Плюрализация и склонения** | В русском 3 формы, в азербайджанском 1, в английском 2; позиционная строка это не описывает. |
| **Порядок слов** | В разных языках части предложения стоят по-разному; склейка по номерам ломается. |
| **Проверка полноты** | Легко пропустить строку: номер есть, текста нет — и никто не заметит. |

### Что не так с клиентской подстановкой

| Проблема | Последствие |
|---|---|
| **SEO** | Поисковик видит один HTML с текстом по умолчанию; ru/en-контент может не индексироваться. |
| **Отдельные URL** | Нельзя поделиться ссылкой на русскую версию страницы; `hreflang` не работает. |
| **LCP/CLS** | Текст появляется после JS — мигание, сдвиг вёрстки, худшие Core Web Vitals. |
| **Доступность** | Скринридер и `lang` атрибут меняются на лету; перевод может не озвучиться правильно. |
| **Кэш** | Один URL — три языка; CDN и браузер кэшируют неправильно. |
| **Отказ JS** | Без JS остаётся только язык по умолчанию. |

**Вывод:** клиентская подстановка экономит файлы, но платит SEO и скоростью. Для сайта, который борется за топ выдачи, это плохая сделка.

---

## 14.3 Лучшее решение: SSG + семантические ключи

Количество **шаблонов** сокращается в 3 раза. Количество **URL** остаётся — потому что каждому языку нужен свой адрес. Но страницы не поддерживаются руками: они **генерируются**.

```
design/
  templates/
    training.html.j2          один шаблон на тип
    consultation.html.j2
    specialist.html.j2
    article.html.j2
content/
  az/
    telim/klinik-psixologiya.yaml
    konsultasiya/depressiya.yaml
  ru/
    telim/klinik-psixologiya.yaml
    konsultasiya/depressiya.yaml
  en/
    ...
```

**Ключи — семантические, не порядковые:**

```yaml
# content/ru/telim/klinik-psixologiya.yaml
hero:
  badge: "Дополнительное образование"
  title: "Клиническая психология"
  lead: "Программа для практикующих психологов"
facts:
  hours: "1 556"
  format: "Онлайн + практика"
program:
  about: "..."
  subjects: ["...", "..."]
price:
  total: "3 600 AZN"
  monthly: "300 AZN"
```

Сборка: `build.py` берёт шаблон + локаль → `az/telim/klinik-psixologiya.html`, `ru/...`, `en/...`.

**Валидатор переводов** (обязателен):

- набор ключей во всех языках **совпадает**;
- нет пустых значений;
- нет лишних ключей;
- длина текста в пределах (для мобильной вёрстки);
- сборка падает, если перевод неполный.

Это даёт ту самую «параллельность 1:1», но устойчивую: ключ не сдвигается при вставке абзаца.

---

## 14.4 Сравнение трёх подходов

| Критерий | Сейчас (3 копии HTML) | Ваша схема (1 HTML + JS-подстановка) | SSG + ключи (рекомендация) |
|---|---|---|---|
| Правка дизайна | в 3 местах | в 1 месте | **в 1 месте** |
| Правка текста | в 3 файлах | в 3 языковых файлах | **в 3 языковых файлах** |
| Число шаблонов | 3 × N | 1 × N | **1 × N** |
| Число URL | 3 × N | N | **3 × N (генерируются)** |
| SEO | хорошо | **плохо** | **хорошо** |
| hreflang / шаринг ссылок | есть | **нет** | **есть** |
| Скорость (LCP) | хорошо | **хуже** | **хорошо** |
| Полнота перевода | глазами | хрупко | **валидатор** |
| Плюрализация | вручную | **не решается** | **ICU / Fluent** |
| Сложность сборки | низкая | средняя | средняя |

---

## 14.5 Что рекомендую внедрить

1. **Шаблоны Jinja2** на каждый тип страницы (9 типов), а не на каждую страницу.
2. **Контент в YAML/JSON** с семантическими ключами, по языкам.
3. **Сборка статических страниц** для каждого языка — отдельные URL, hreflang.
4. **Валидатор ключей** в `verify.py`: неполный перевод → сборка красная.
5. **Книги** — манифест + `books/<slug>/<lang>/`, языки из манифеста.
6. **ICU MessageFormat** (или Fluent) для плюрализации и вставок, если появятся формы «1 сессия / 2 сессии / 5 сессий».
7. **Не делать** клиентскую подстановку текста и номера строк.

Это и есть мировой стандарт для статических многоязычных сайтов: SSG + i18n-ключи + отдельные URL. Он даёт ваш выигрыш (один дизайн, один шаблон, тексты отдельно) без потери SEO и скорости.
