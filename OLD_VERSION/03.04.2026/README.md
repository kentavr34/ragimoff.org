# ragimoff.org (статический сайт)

Этот репозиторий — **статический HTML/CSS/JS-сайт**. Сборки (npm/webpack) нет: страницы открываются напрямую или через локальный static-server.

## Быстрый старт (локально)

### Вариант A — просто открыть файл
- Откройте `index.html` двойным кликом в браузере.

Минус: некоторые вещи (CSP, относительные пути, редиректы) удобнее проверять через сервер.

### Вариант B — локальный сервер (рекомендуется)

Любой static-server подойдёт. Примеры:

- Python:

```bash
python -m http.server 8080
```

- Node (если установлен):

```bash
npx serve .
```

Дальше откройте `http://localhost:8080/` (или адрес, который покажет команда).

## Что где лежит

- **Страницы**: корень проекта (`*.html`)
  - `index.html` — главная (самая “тяжёлая”: много инлайн-CSS/JS).
  - `3.html`, `5.html`, `2.html` — лендинги/страницы образования.
  - `tehsil.html` — “Тəhsil” (2 вкладки, аккордеон, форма регистрации).
  - `haqqimda.html` — “Обо мне” + дипломы/галереи.
  - `blog*.html`, `blog-posts/index.html` — блог.

- **Общий JS**: `shared.js`
- **Данные**: `data/*.json` (например, цены/сертификаты)
- **Изображения**: `images/`
- **Деплой/хостинг**:
  - `netlify.toml` — редиректы и заголовки для Netlify

- **Админка**: `admin/` (CMS-конфиг)

## Ключевые принципы поддержки (важно для следующего разработчика)

### 1) Mobile-first и единая сетка
Базовая логика адаптива уже есть в `shared.css` (брейкпоинты ~768px и ~1024px). Любые новые секции добавляем сначала под 320–480px.

### 2) Источник правды по UI-компонентам
В проекте есть два подхода:
- **Общий подход**: повторно используемые компоненты (header, footer, кнопки, базовые карточки, мобильное меню, анимации появления) живут в `shared.css`/`shared.js`.
- **Страничный подход**: некоторые страницы имеют большой инлайн‑CSS/JS (особенно `index.html`, `tehsil.html`), что может **дублировать** поведение из `shared.*`.

Правило для будущих правок:
- Если правка относится к **общим элементам** (хедер/футер/кнопки/мобильное меню/общие карточки) — правим **`shared.css`/`shared.js`**.
- Если правка относится только к одной странице — правим инлайн в конкретной странице, но **не переопределяем** одинаковые функции/классы без необходимости.

### 3) Известная “мина”: мобильное меню и дубли функций
На разных страницах встречаются разные схемы открытия мобильного меню:
- `.mobile-nav.open` (типично для `shared.css` и большинства страниц)
- `.mobile-nav.show` (используется в `index.html` вместе с инлайн‑CSS/JS)

Также на главной странице есть инлайн‑JS, который **переопределяет** функции из `shared.js` (`toggleMenu`, `closeMenu`, анимации через `IntersectionObserver`, submit формы и т.д.).

Если вы будете “чинить меню/анимации”, обязательно проверьте:
- работает ли это на **`index.html`** и на любой другой странице (например, `5.html` или `haqqimda.html`);
- не конфликтуют ли одинаковые имена функций.

## Как вносить правки безопасно

- **Проверяйте на 3 ширинах**: ~360px, ~768px, ~1280px.
- **Проверяйте навигацию**: header links, якоря (`#...`), кнопки CTA, WhatsApp.
- **Не ломайте единый стиль**: палитра и типографика описаны в `DESIGN_MASTERPLAN.md`.

## Деплой (Netlify)

Проект рассчитан на статический хостинг. Для Netlify поведение задаёт `netlify.toml`:
- редиректы (например, `/3` → `/3.html`)
- кеширование для `.css`, `.js`, `/images/*`

## Админка (/admin) — вариант 2 (GitHub OAuth)

Админка сделана на **Decap CMS** и в этом варианте работает так:
- CMS открывается по `/admin/`
- логинится через GitHub OAuth (эндпоинты `/auth` и `/callback`)
- после логина пишет изменения прямо в репозиторий, указанный в `admin/config.yml`

### 1) Создать GitHub OAuth App

В GitHub откройте:
`Settings` → `Developer settings` → `OAuth Apps` → `New OAuth App`

- **Homepage URL**: `https://ragimoff.org`
- **Authorization callback URL**: `https://ragimoff.org/callback`

### 2) Прописать секреты в окружении хостинга

Нужно добавить переменные окружения (на хостинге, где выполняются serverless‑функции):

- `OAUTH_CLIENT_ID` — Client ID из GitHub OAuth App
- `OAUTH_CLIENT_SECRET` — Client Secret из GitHub OAuth App
- `ORIGINS` — разрешённые origin’ы, например: `https://ragimoff.org`
- (опционально) `OAUTH_SCOPE` — scope для GitHub, по умолчанию `repo`

### 3) Как это подключено в проекте

- `admin/config.yml`:
  - `backend: github`
  - `repo: kentavr34/ragimoff.org`
  - `base_url: https://ragimoff.org` (там ожидаются `/auth` и `/callback`)
- `netlify.toml` проксирует:
  - `/auth` → `/.netlify/functions/auth`
  - `/callback` → `/.netlify/functions/callback`
- функции лежат в `netlify/functions/`

Если хостинг **не Netlify**, то нужно обеспечить, чтобы по путям `/auth` и `/callback` работал ваш OAuth‑сервер (можно развернуть эти же обработчики на любом serverless/VM).
